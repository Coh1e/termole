# 宿主能力契约草案

状态：依据已确认架构细化；T01 已实现首批 C ABI / C++23 子集（见 [termole.h](../include/termole/termole.h) 与 [t01-validation.md](t01-validation.md)），完整二进制接口尚未冻结，首版不包含 QuickJS。

## 统一契约

这里的 IR 是终端领域的类型化操作、查询和事件，不是序列化协议、字节码或通用执行语言。原生 C++ 调用、C ABI 和未来 QuickJS 绑定最终进入同一份校验与执行逻辑，不各自实现业务规则。

| 族 | 主要内容 | 约束 |
| --- | --- | --- |
| 会话操作 | CreateSession、TerminateSession | 程序、参数、工作目录、环境变量分别传递；不自行拼 Shell 管道 |
| 终端操作 | SendText、SendKey、Resize | 粘贴与按键是不同意图，由核心按当前终端模式编码 |
| 视图操作 | CreateView、DestroyView、ApplyAppearance、Scroll、Select、Copy、Paste | 在宿主 UI 线程执行；子窗口布局由宿主负责 |
| 查询 | State、Size、Title、Selection、ExitCode | 快照有明确所有权，退出码在退出完成前不可用 |
| 事件 | TitleChanged、Bell、Exited、Error | 通过宿主可调度队列交付，不在 I/O 线程调用宿主 UI |

T01 的首批实现额外提供 `termole_session_get_screen_text`：返回可见屏幕的 UTF-8 快照，供宿主诊断、无障碍或验收读取；它不是选择查询，也不暴露 VT 引擎内部状态。完整事件与查询契约仍按后续任务冻结。

T02 将 ABI 升级到 2：`termole_session_options` 分别接收 program、逻辑 argv 数组、工作目录和 `KEY=VALUE` 环境数组。参数不经过字符串拼接，空参数与 Unicode 保真；环境数组在调用方环境副本上覆盖，不修改调用方进程。

CreateView 附加既有会话；同一会话已有 View 时返回明确错误。T01 已用每 Session 的 attach 标志强制该约束，重复附加返回 `TERMOLE_STATUS_INVALID_STATE`。DestroyView 不结束会话；会话本身仍消费输出并保留有界历史。关闭独立窗口是应用层先终止会话再销毁视图，不在基础 View 析构中隐藏进程终止策略。

## C ABI 与数据所有权

- 导出 C 函数及不透明 context/session/view 句柄；不暴露 STL、C++ 异常、VT 引擎和 Direct2D 内部类型。
- 调用方与 DLL 协商 ABI 主版本；可扩展结构携带尺寸字段，布局和调用约定在冻结前明确。
- 输入数据在调用期间有效；若操作需要异步保留，库负责复制，不能保留宿主临时指针。
- 返回的库分配数据通过配套释放函数归还库，宿主不得跨运行时直接释放。
- 错误分为参数/状态错误、系统错误、依赖错误；返回稳定类别及诊断，不把 HRESULT/系统错误数字当成唯一领域契约。
- C++23 包装只承担 RAII、类型与结果转换，复用 C ABI 行为；未来脚本绑定也不穿透核心内部结构。

## 事件和销毁

宿主在 UI 线程调度事件分发。队列唤醒只表示有工作，不携带裸 Session/View 指针；销毁后的句柄不能被排队事件重新使用。Exited 在主进程结束且该会话输出排空后报告。需要在实现前用具体测试明确：排队事件后销毁 View、从事件处理中请求终止、宿主销毁 context。

队列容量、合并策略与输出排空的截止策略尚待实现阶段测定；不能让响铃或标题洪泛无限增加内存，也不能为等子进程持有的输出句柄无限等待退出。

## 未来脚本宿主能力

脚本上下文只接收宿主授予的操作和资源范围。既有会话引用不等于允许创建任意进程；终端输出也不能为脚本授予能力。文件、网络不提供通用脚本 API；剪贴板访问沿用宿主授权。

QuickJS 后续接入时才决定引擎版本、执行线程、事件回调、资源上限和中断机制。当前不为尚未接入的引擎引入构建依赖，也不实现自定义解释器。
