# 原生嵌入与视图定制

状态：部分由 [ADR 0018](0018-quickjs-plugins.md) 取代。进程模型、视图外观和实例隔离仍适用。下文面向第三方的静态 SDK 分发及仓库外宿主验收是原决定，已退出交付计划。

嵌入宿主可以在自己的进程内使用 SDK，管理会话和视图。需要在宿主退出后保留 Shell 并稍后重连时，显式启动本地会话服务。视图与会话的所有权遵循 [ADR 0010](0010-window-definitions.md)，现有连接行为见[本地会话](../cli.md#本地会话)。

独立入口读取用户 TOML 和配置组。嵌入时由宿主选择配置来源，通过 SDK 显式传入设置，以保留宿主对窗口布局和错误提示的控制。

宿主可在会话运行期间修改指定视图的字体、字号、配色和内边距。影响可用网格的变更须重新计算行列数，并将变化同步到对应 PTY。保留原 Shell、回滚内容和其他独立视图的设置。

下一阶段使用仓库外的 Win32 CMake 工程验收。宿主仅依赖静态 SDK 分发包和公开文档，创建两个各自运行 Shell 的视图并输入命令。在第一个视图中分别修改四项设置，包括把字号从 11 pt 调到 14 pt；验证网格、PTY 尺寸和回滚内容，再销毁该视图。第二个视图应始终保持原字号和尺寸，原 Shell 能继续处理输入。

首版允许宿主为每个视图分别覆盖默认前景色、默认背景色和选区背景色。每项可单独指定，未指定的颜色继承该视图当前主题。终端程序显式指定的文本颜色继续生效。

宿主可在运行时单独撤销任一颜色覆盖。该项立即恢复为当前主题的对应颜色，并随之后的主题切换更新。其他项保留各自的覆盖或继承状态。

配色验收时，只覆盖第一个视图的默认背景色，核对其默认前景色和选区背景色仍取自主题；再分别修改这两项。用含默认文本和显式着色文本的输出核对颜色优先级，并对照第二个视图验证修改仅作用于目标视图。保留截图或像素证据。

在三个颜色均已覆盖时，单独撤销背景色，核对其立即恢复为主题背景色。再切换该视图的主题，核对背景随之更新，前景色和选区背景色仍为宿主指定值。对其余两项分别验证相同的撤销行为。

DLL 分发留待具体宿主的部署需求明确后决定。跨进程修改外观的控制接口另行讨论。
