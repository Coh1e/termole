# QuickJS 插件与原生 SDK 的定位

状态：已采纳。

第三方开发者按 Termole 定义的 JavaScript 接口编写插件。Termole 负责窗口、会话、原生渲染以及向插件开放的操作，通过嵌入的 QuickJS 执行插件。借鉴 Zellij 的宿主与插件分工；Zellij 的 Wasm 插件及其 API 兼容性不在交付范围内。

Windows Applet 继续通过公开 CLI 调用外部 TUI。现有原生 SDK ABI 3 和脚本接口按兼容基线维护。[ADR 0017](0017-native-embedding.md) 中面向第三方分发原生 SDK 的承诺及其仓库外宿主交付门槛由本决定取代。

现有可选脚本引擎提供上下文创建、求值和销毁接口。首个插件验收场景为“复制选区为 Markdown 引用”。插件向宿主注册一个由用户主动触发的命令。用户在视图中选中文本并执行命令后，插件通过宿主读取该视图的选区，在每行开头加上 `> `，再通过宿主将结果写入剪贴板。首例用到的宿主能力为注册命令、读取当前选区和写入剪贴板。

验收时，在同一视图选中以下两行并执行命令：

```text
第一行
second line
```

将剪贴板粘贴到文本编辑器，预期得到：

```text
> 第一行
> second line
```

首版仅加载用户在配置中显式启用的本地 `.js` 文件。验收时，将示例插件的路径加入配置，重启 Termole，再执行上述选区命令。随后移除该配置项，保留磁盘上的插件文件并再次重启，确认该命令不再注册。

官方独立终端发布单一标准包，发布构建显式设置 `TERMOLE_WITH_QUICKJS=ON`，静态内置 QuickJS。用户无需另装引擎。只有配置中显式启用了本地插件，终端才创建插件运行时。通用源码构建保留同一 CMake 开关，默认值为 `OFF`，供自行构建精简版本使用。

用待发布的标准包直接验收上述插件场景。评估分发体积时，在同一平台、工具链和 Release 配置下对照开关两种取值，记录实际产物大小及差值。

首个插件的配置项和接口见 [本地 QuickJS 插件](../config.md#本地-quickjs-插件)。
