# ADR 0016：跨平台 C 核心与 CMake

- 状态：accepted
- 日期：2026-11-21

## 决策

- 跨平台是整个架构的约束。共享逻辑选用可移植 C。窗口、渲染、PTY、IPC 传输和其他系统服务在各自的边界内适配 Windows、Linux 和 macOS。共享核心接口只暴露平台无关类型。
- 通过稳定、可版本化的 C ABI 保持核心和外围解耦。接口明确类型、所有权、生命周期和错误语义。外围可以用 Zig、Rust 或 C++ 实现、替换和链接。C++ 类型和异常留在实现侧。
- 能用 C 实现的逻辑用 C。只有现代 C++ 在资源生命周期、类型安全或复杂平台 API 封装上有明确优势时，才在对应模块使用 C++23/26。引入时说明具体收益，并核对支持平台的工具链。既有模块的语言和代码行数比例不构成选型依据。
- 项目构建与第三方依赖集成统一由 CMake 管理。依赖通过 CMake 目标接入，例如固定版本的 `FetchContent` 或导入静态库。功能、许可和平台支持相当时优先选择单头文件库。禁止使用 vcpkg、Conan 或同类依赖管理器。

## 静态链接

- Windows 静态链接第三方依赖和 MinGW 运行库，系统 API 通过 Windows 系统库调用。
- Linux 静态链接产品依赖。交付目标要求消除 glibc 依赖时使用 musl。glibc 静态构建的验证结果按实测环境记录。
- macOS 静态链接第三方依赖，系统框架采用平台提供的动态链接方式。

## 依赖选型

- 可独立提供所需能力且依赖范围合适的库可直接复用。若只需一项行为，引入整个组件却会带来额外依赖，则参考上游行为实现所需部分，并用测试验证。技术探针使用的库进入产品前也须按此评估。
- 复制或改编上游代码时，保留来源和许可证声明。参考上游行为自行实现时，记录行为出处和验证用例，覆盖相关的终端控制序列、Unicode 或输入法边界。

平台工具链及构建步骤见[跨平台构建手册](../cross-platform-build.md)。
